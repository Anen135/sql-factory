# SQL Trainer

Статический учебный SQL-тренажёр для студентов 15–16 лет: тёмный crimson-интерфейс, 24 задачи, Monaco Editor, проверка результата и настоящий пошаговый разбор данных. Backend, регистрация и API-ключи не нужны.

## Запуск

Нужен Node.js 22 или новее.

```bash
npm ci
npm run dev
```

Откройте адрес, который выведет Vite. Начальный экран — задача 22 «Средняя оценка студентов». Она содержит редактируемый рабочий запрос, чтобы сразу попробовать визуализацию. Для остальных задач задан каркас SELECT.

```bash
npm test          # SQL-логика и весь каталог задач
npm run build    # проверка TypeScript и production-сборка
npm run preview  # просмотр dist через HTTP
```

Не открывайте index.html двойным кликом: ES modules, Web Workers и WASM требуют HTTP. Monaco, его worker и SQLite WASM входят в сборку, CDN для выполнения кода не используется. Шрифт Manrope также входит в сборку; внешние CDN и Google Fonts не нужны.

## Что реализовано

- Dashboard с реальным прогрессом и учебными модулями.
- Каталог: темы, сложность, решённые/сохранённые задачи, поиск в верхней панели на широком экране.
- Рабочий экран задачи: условие, ожидаемые имена столбцов, последовательные подсказки, схемы и пример решения.
- Monaco с подсветкой SQL, сбросом запроса и Ctrl/Cmd+Enter.
- Выполнение SELECT в отдельном Web Worker, результат, ошибки, проверка по эталону.
- Визуализация входа и выхода каждого применимого этапа, промежуточный SQL и логический план.
- Справочник, просмотр исходных таблиц, свободная песочница `#/sandbox`.
- Закладки, черновики и решения сохраняются Zustand persist в localStorage этого браузера.
- Адаптивный layout, клавиатурные focus states, поддержка reduced motion.
- Профиль показывает решённые задачи и прогресс по темам из Local Storage.

## Архитектура

```text
src/
  components/                  # таблица результатов
  layout/                      # шапка и дерево задач
  pages/                       # задача, каталог, dashboard, справочник, база
  features/
    tasks/types.ts             # контракты Task, Execution, Step, TableData
    sql-editor/                # Monaco, локальный worker и тема
    sql-visualizer/             # вход/выход этапов
    database/
      client.ts                # запросы worker, timeout и завершение worker
      sql.worker.ts            # загрузка WASM, создание базы, освобождение
      engine.ts                # AST, выполнение, сравнение, логический разбор
      engine.test.ts           # проверки каталога и семантики
  data/
    database.ts                # схема и воспроизводимый SQL seed
    tasks.ts                   # расширяемый каталог
  store/                       # локальные черновики, закладки, прогресс
  styles.css                   # дизайн-система и адаптивность
e2e/                           # браузерные сценарии
```

React/TypeScript отвечают за UI, Vite — за статические ресурсы. SQL.js выполняет запросы в SQLite WASM. Node-sql-parser читает SQL в диалекте MySQL и строит AST; SQL не разбирается регулярными выражениями. Каждый запуск получает новую базу, поэтому студенты не могут повредить исходные данные. Worker завершается после ответа или тайм-аута 8 секунд. Результат ограничен 5000 строками, таблицы интерфейса показывают первые 100 (промежуточные — 20), сохраняя полный результат для проверки.

## Как добавлять задачи

Добавьте объект `Task` в `src/data/tasks.ts` (или используйте локальную фабрику `make`):

```ts
{
  id: 25,
  title: 'Студенты группы 1',
  category: 'Фильтрация',
  difficulty: 'Легко',
  statement: 'Выведите имена студентов группы 1.',
  hints: ['Используйте WHERE group_id = 1.'],
  tables: ['students'],
  expectedColumns: ['name'],
  sampleQuery: 'SELECT name FROM students WHERE group_id = 1;',
  starter: 'SELECT name FROM students;',
  ordered: false,
  tags: ['WHERE']
}
```

`id` должен быть уникальным. `tables` определяет карточки схемы, а не права доступа. Все задачи используют общий seed; новые таблицы добавляются в `schema` и `seed` в `database.ts`. Для нового раздела дополните `categories`.

Эталонный запрос выполняется на той же базе. Сравниваются имена и порядок колонок, значения и количество повторяющихся строк. При `ordered: false` порядок строк не важен; при `true` сравнивается точно. Числа нормализуются до 6 знаков после запятой. NULL отличается от строки и числа. Задавайте дополнительные ключи ORDER BY, если хотите устойчивый порядок при одинаковых значениях.

Это проверка результата на демонстрационных данных, а не доказательство корректности на всех возможных наборах. Альтернативный SQL с правильным результатом принимается. Требование использовать конкретную конструкцию (например EXISTS) носит учебный характер и отдельно не проверяется. Следующее расширение для более строгой проверки — несколько seed-наборов на задачу.

## Как устроена визуализация

1. Парсер проверяет, что введён один SELECT, и создаёт AST.
2. Исходный запрос исполняется движком; ответ проверяется независимо от визуализатора.
3. Из AST последовательно строятся промежуточные запросы: FROM → каждый JOIN → WHERE → GROUP BY → AGGREGATE → HAVING → SELECT → ORDER BY → LIMIT. Отсутствующие конструкции пропускаются.
4. Каждый промежуточный запрос реально выполняется. Снимок предыдущего этапа становится входом следующего.
5. GROUP BY показывает ключи групп и `строк_в_группе`; AGGREGATE показывает вычисленные агрегаты и выражения над ними. Чтобы не выводить недетерминированные негруппированные столбцы, агрегатный снимок использует выражения SELECT; итоговый SELECT объясняет проекцию и псевдонимы. Это учебная модель логического порядка, не внутренние операции оптимизатора.

Нижняя лента объясняет универсальный порядок; кнопка «Посмотреть на своих данных» запускает настоящий разбор. Во вкладке «Визуализация» выбирайте этапы своего запроса и смотрите таблицы до/после. Вкладка «План выполнения» показывает этот логический план, **не EXPLAIN**.

## SQL: поддержка и ограничения

Проверены SELECT *, выбор полей, AS, DISTINCT, WHERE, AND/OR, IN, BETWEEN, LIKE, IS NULL, ORDER BY, LIMIT, INNER/LEFT JOIN, несколько JOIN, GROUP BY, HAVING, COUNT/SUM/AVG/MIN/MAX, ROUND, скалярные подзапросы, IN (SELECT), EXISTS и коррелированные подзапросы в WHERE.

**Движок — SQLite, не сервер MySQL.** Каталог использует общее подмножество SQL. Не эмулируются MySQL DATE_FORMAT/CONCAT, серверная типизация, collation, режим ONLY_FULL_GROUP_BY и другие особенности. Сравнение и сортировка строк подчиняются SQLite (в частности, бинарная сортировка кириллицы). SQLite может разрешить негруппированные столбцы, которые строгий MySQL отклонит; в учебных решениях явно перечисляйте ключи GROUP BY.

Для CTE, UNION, оконных функций и FROM-подзапросов пошаговая визуализация не реализована: если запрос проходит парсер и движок, результат остаётся доступен, а визуализатор сообщает ограничение. Вложенные подзапросы в WHERE исполняются, но не раскрываются в отдельную внутреннюю анимацию. Неподдерживаемая промежуточная конструкция не превращается в выдуманные данные. DDL/DML и несколько SQL-выражений за один запуск запрещены.

## GitHub Pages

1. Загрузите проект в GitHub-репозиторий в ветку `main`.
2. В **Settings → Pages → Build and deployment** выберите **GitHub Actions**.
3. Workflow `.github/workflows/deploy.yml` выполнит `npm ci`, тесты и сборку, затем опубликует `dist`.
4. Откройте URL из job `deploy`. Публикация из локальной среды автоматически не выполняется.

`base: './'` в Vite делает JS, CSS, Monaco Worker и WASM относительными, поэтому сборка работает как на `username.github.io`, так и на `username.github.io/repository/`. Hash-навигация (`#/task/22`) не требует серверного fallback и сохраняется при обновлении страницы. При иной основной ветке измените `on.push.branches` в workflow.

Для ручной публикации разместите **содержимое** `dist` в выбранной Pages-ветке. Не публикуйте `node_modules`.

## Проверки браузера

```bash
npx playwright test
npx playwright test --config playwright.production.config.ts # после npm run build
```

Конфигурация использует установленный Microsoft Edge (`channel: 'msedge'`). Если его нет, установите браузер через `npx playwright install msedge` либо замените канал на установленный Chromium. Проверяются Monaco, SQL Worker/WASM, правильное решение, визуализация, сохранение прогресса, навигация, просмотр таблиц, фильтры и отсутствие горизонтального переполнения на 390 px. Отдельная production-конфигурация проверяет запуск по вложенному пути `/sql-factory/`, включая загрузку WASM и worker. Скриншоты записываются в `artifacts/` и не входят в репозиторий.

## Дальнейшее развитие

Слои данных и выполнения отделены от UI: можно добавить несколько датасетов на задачу, worker pool, AST-проверку обязательных конструкций, визуализацию вложенных подзапросов и импорт/экспорт прогресса. Приложение остаётся полностью статическим.


Оформление использует предоставленные материалы из images: background.png, logo.png, icon.png; style-sheet.png и maskot.png служат дизайн-референсами.
